# Glossary

Alphabetical within each section. If a term is missing, add it in a PR!

## Cybersecurity

| Term | Meaning |
|---|---|
| **ALPHV / BlackCat, Cl0p, LockBit, Conti** | Examples of ransomware groups/operations referenced in public reporting |
| **ATT&CK (MITRE)** | Knowledge base of attacker tactics & techniques |
| **CNA** | CVE Numbering Authority: organization allowed to assign CVE IDs |
| **CPE** | Standard naming scheme for products/versions |
| **CVE** | Unique ID for a publicly known vulnerability |
| **CVSS** | 0–10 severity score for vulnerabilities |
| **CWE** | Category of software weakness (e.g. CWE-89 SQL injection) |
| **Double extortion** | Encrypt data *and* threaten to leak stolen data |
| **EPSS** | Probability a CVE will be exploited in the next 30 days |
| **Exploit** | Code/technique that takes advantage of a vulnerability |
| **IR** | Incident response |
| **KEV** | CISA's Known Exploited Vulnerabilities catalog |
| **NVD** | NIST's National Vulnerability Database |
| **Patch** | Software update that fixes a vulnerability |
| **RaaS** | Ransomware-as-a-Service |
| **RCE** | Remote code execution: attacker runs code on the victim machine remotely |
| **Supply-chain attack** | Compromise of a supplier whose customers are then affected |
| **Zero-day** | Vulnerability exploited before a fix exists |

## Finance & regulation

| Term | Meaning |
|---|---|
| **8-K** | Current report for significant unscheduled events |
| **8-K Item 1.05** | Material cybersecurity incident disclosure |
| **10-K** | Annual report |
| **10-K Item 1A** | Risk Factors |
| **10-K Item 1C** | Cybersecurity (risk management & governance) |
| **10-Q** | Quarterly report |
| **Abnormal return (AR)** | Actual return minus expected return |
| **Accession number** | Unique ID of an EDGAR filing |
| **CAR** | Cumulative abnormal return over an event window |
| **CIK** | Central Index Key: permanent EDGAR company ID |
| **EDGAR** | SEC's public filing database |
| **Event study** | Method to measure an event's effect on stock price |
| **MD&A** | Management's Discussion & Analysis (10-K Item 7) |
| **Material** | Significant enough that a reasonable investor would consider it important |
| **SEC** | US Securities and Exchange Commission |
| **XBRL** | XML-based tagging of financial data in filings |

## AI / ML / RAG

| Term | Meaning |
|---|---|
| **Agent** | LLM system that can decide to call tools and take multi-step actions |
| **BM25** | Classic keyword ranking function (sparse retrieval) |
| **Chunk** | A passage of a document stored/retrieved as a unit |
| **Context window** | Max tokens an LLM can read at once |
| **Cosine similarity** | Angle-based similarity between vectors |
| **Cross-encoder** | Model scoring (query, passage) jointly; used for reranking |
| **Embedding** | Vector representation of text |
| **Faithfulness / groundedness** | Whether an answer's claims are supported by the retrieved context |
| **Golden set** | Curated test questions with verified answers |
| **Guardrails** | Checks/filters/policies around model inputs and outputs |
| **Hallucination** | Fluent output not supported by facts or sources |
| **Hybrid search** | Combining sparse and dense retrieval |
| **LLM-as-judge** | Using an LLM to grade other outputs |
| **MRR / nDCG / Recall@k** | Ranking metrics for retrieval |
| **Prompt injection** | Input (direct or hidden in documents) that overrides the model's instructions |
| **RAG** | Retrieval-Augmented Generation |
| **Reranking** | Re-ordering retrieved candidates with a stronger model |
| **Red teaming** | Systematically attacking your own system to find weaknesses |
| **Token** | Sub-word unit LLMs read/write |
| **Vector store** | Database optimized for nearest-neighbor search on embeddings |
